# Plan 02-02: Implement Active Role State, HTTP Interceptor, and Role-Aware UI Controls

<objective>
Implement active role management with `localStorage` persistence in `TaskFlowService` per PROF-03, build and register an Angular `HttpInterceptorFn` transmitting the `x-user-role` header on all outgoing requests per PROF-04, and enforce role-aware UI button states and drag disabling per PROF-05. Verify through Angular unit tests.
</objective>

<tasks>
<task type="auto" tdd="true">
  <name>Task 1: Implement Role state in TaskFlowService and authRoleInterceptor</name>
  <files>
    frontend/src/app/services/taskflow.service.ts,
    frontend/src/app/services/auth-role.interceptor.ts,
    frontend/src/app/app.config.ts
  </files>
  <read_first>
    frontend/src/app/services/taskflow.service.ts,
    frontend/src/app/app.config.ts,
    frontend/src/app/models/taskflow.model.ts,
    .planning/phases/02-frontend-user-profile-role-context/02-CONTEXT.md
  </read_first>
  <behavior>
    - TaskFlowService exposes activeRole signal initialized from localStorage ('taskflow_active_role') defaulting to 'MEMBER'
    - setRole(role: UserRole) updates activeRole signal and saves to localStorage
    - authRoleInterceptor injects 'x-user-role' header with the current active role on every HTTP request
  </behavior>
  <action>
    1. In frontend/src/app/services/taskflow.service.ts:
       - Import `signal` from `@angular/core` and `UserRole` from `../models/taskflow.model`.
       - Add `private readonly ROLE_STORAGE_KEY = 'taskflow_active_role';`
       - Initialize `activeRole = signal<UserRole>(this.getInitialRole());`
       - Helper `private getInitialRole(): UserRole`: reads localStorage.getItem(this.ROLE_STORAGE_KEY). Validates against 'ADMIN' | 'MEMBER' | 'VIEWER', returns 'MEMBER' as default fallback.
       - Method `setRole(role: UserRole): void`: updates `this.activeRole.set(role)` and writes `localStorage.setItem(this.ROLE_STORAGE_KEY, role)`.
    2. Create `frontend/src/app/services/auth-role.interceptor.ts`:
       - Export `authRoleInterceptor: HttpInterceptorFn = (req, next) => { ... }`:
         - Injects `TaskFlowService`.
         - Reads `role = taskFlowService.activeRole()`.
         - Clones request with `.clone({ setHeaders: { 'x-user-role': role } })`.
         - Returns `next(clonedReq)`.
    3. In frontend/src/app/app.config.ts:
       - Import `withInterceptors` from `@angular/common/http`.
       - Import `authRoleInterceptor` from `./services/auth-role.interceptor`.
       - Update `provideHttpClient()` to `provideHttpClient(withInterceptors([authRoleInterceptor]))`.
  </action>
  <verify>
    <automated>npm run build:frontend</automated>
  </verify>
  <done>TaskFlowService role state and authRoleInterceptor compile cleanly into application bundle.</done>
</task>

  <name>Task 2: Adapt UI controls to active role and verify with unit tests</name>
  <files>

  </files>
  <read_first>
    frontend/src/app/app.ts,
    frontend/src/app/app.html,
    frontend/src/app/app.spec.ts
  </read_first>
  <action>
    1. In frontend/src/app/app.ts:
       - Expose `activeRole = this.taskflowService.activeRole;`
       - Add computed signals:
         - `canDeleteProject = computed(() => this.activeRole() === 'ADMIN');`
         - `canMutateTasks = computed(() => this.activeRole() !== 'VIEWER');`
         - `canCreateProject = computed(() => this.activeRole() !== 'VIEWER');`
       - Add handler `onRoleChange(newRole: UserRole)`:
         - Calls `this.taskflowService.setRole(newRole);`
         - Triggers notification: `this.showNotification('Switched Role', 'Active role changed to ' + newRole + '. Permissions updated.', 'info');`
    2. In frontend/src/app/app.html:
       - Delete project button:
         `[disabled]="!canDeleteProject()"`
         `[title]="canDeleteProject() ? 'Delete current project' : 'Only ADMIN can delete projects'"`
       - `+ New Project` button:
         `[disabled]="!canCreateProject()"`
         `[title]="canCreateProject() ? 'Create new project' : 'VIEWER role has read-only access'"`
       - `+ New Task` button:
         `[disabled]="!canMutateTasks() || !selectedProjectId()"`
         `[title]="canMutateTasks() ? 'Create new task' : 'VIEWER role has read-only access'"`
       - Kanban cards:
         `[cdkDragDisabled]="!canMutateTasks()"`
         Add visual hint/badge when in read-only mode if needed.
    3. In frontend/src/app/app.spec.ts:
       - Verify existing tests continue passing. Add test checking that `ProfileComponent` is included in App and `activeRole` defaults to a valid role.
  </action>

    <automated>npm run build:frontend</automated>
  </verify>
