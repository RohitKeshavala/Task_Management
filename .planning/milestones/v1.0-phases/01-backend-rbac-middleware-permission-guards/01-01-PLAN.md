# Plan 01-01: RBAC Authentication Middleware, Error Hierarchy, and Permission Guards

<objective>
Implement core authentication and role-based access control primitives in the Express backend per D-01, D-02, D-03, D-04, D-09, D-10, D-11. Defines the `UserRole` type and allowed roles, creates `ForbiddenError` extending `AppError`, provides `authMiddleware` to normalize and validate the `x-user-role` header with a default of `MEMBER`, and implements the `requireRole` guard helper.
</objective>

<tasks>
<task type="auto" tdd="true">
  <name>Task 1: Define UserRole types, ForbiddenError, and authMiddleware + requireRole guard</name>
  <files>
    backend/src/types/errors.ts,
    backend/src/types/index.ts,
    backend/src/middleware/auth.ts
  </files>
  <read_first>
    backend/src/types/errors.ts,
    backend/src/types/index.ts,
    backend/src/middleware/errorHandler.ts,
    .planning/phases/01-backend-rbac-middleware-permission-guards/01-CONTEXT.md
  </read_first>
  <behavior>
    - Missing x-user-role header assigns req.userRole = 'MEMBER'
    - Whitespace or empty x-user-role header assigns req.userRole = 'MEMBER'
    - 'admin' / 'ADMIN ' normalizes to 'ADMIN'
    - 'viewer' normalizes to 'VIEWER'
    - 'INVALID_ROLE' returns 400 Bad Request with error and message detailing valid roles
    - ForbiddenError has statusCode 403 and payload { error: 'Forbidden', message: ... }
    - requireRole(['ADMIN']) allows ADMIN and rejects MEMBER/VIEWER with 403
  </behavior>
  <action>
    1. In backend/src/types/errors.ts, export `ForbiddenError` extending `AppError`:
       Set statusCode = 403, name = 'ForbiddenError', extra = { error: 'Forbidden' }.
       Constructor accepts `(message: string = 'User role is not authorized to perform this action', role?: string)`.
    2. In backend/src/types/index.ts:
       Export `export type UserRole = 'ADMIN' | 'MEMBER' | 'VIEWER';`
       Export `export const VALID_USER_ROLES: readonly UserRole[] = ['ADMIN', 'MEMBER', 'VIEWER'] as const;`
       Re-export ForbiddenError from ./errors.js.
    3. In backend/src/middleware/auth.ts:
       Augment Express Request namespace:
       declare global { namespace Express { interface Request { userRole: UserRole; } } }
       Implement and export `authMiddleware(req: Request, res: Response, next: NextFunction)`:
       - Extract raw header: req.header('x-user-role') || req.headers['x-user-role'].
       - If null, undefined, or empty/whitespace string: assign req.userRole = 'MEMBER'; return next();
       - Trim and uppercase raw header.
       - If valid UserRole: assign req.userRole = normalized as UserRole; return next();
       - If invalid: return res.status(400).json({ error: 'Invalid role', message: `Invalid role: ${rawHeader}. Allowed roles: ${VALID_USER_ROLES.join(', ')}` });
       Implement and export `requireRole(allowedRoles: UserRole[])`:
       - Returns middleware (req: Request, res: Response, next: NextFunction) => {
           if (allowedRoles.includes(req.userRole)) { return next(); }
           return next(new ForbiddenError(`Role ${req.userRole} is not authorized to perform this action`, req.userRole));
         }
  </action>
  <verify>
    <automated>npx tsc -p backend/tsconfig.json --noEmit</automated>
  </verify>
  <done>UserRole types, ForbiddenError, authMiddleware, and requireRole guard compile cleanly under TypeScript strict mode.</done>
</task>
