# Plan 03-01: Backend Authentication Endpoints, Database Schema, Password Hashing & Admin Role Management

<objective>
Implement the backend authentication foundation and admin role management system: SQLite `users` table, secure salted password hashing via Node.js `crypto`, registration/login endpoints, current user introspection, admin-only user listing and role mutation endpoints with demotion safeguard, and comprehensive automated test coverage in `backend/tests/auth.test.ts`.
</objective>

<tasks>
<task type="auto" tdd="true">
  <name>Task 1: Create users schema, password hasher, and AuthService</name>
  <files>
    backend/src/db/database.ts,
    backend/src/types/auth.ts,
    backend/src/types/index.ts,
    backend/src/services/authService.ts
  </files>
  <behavior>
    - users table in SQLite stores id (TEXT PRIMARY KEY), username (TEXT UNIQUE), email (TEXT UNIQUE), password_hash (TEXT), salt (TEXT), role (TEXT NOT NULL DEFAULT 'MEMBER'), created_at, updated_at
    - Password hashing uses crypto.randomBytes(16) for salt and crypto.scryptSync(password, salt, 64)
    - seedInitialData creates admin user 'admin@taskflow.dev' (username: 'admin', password: 'Admin123!', role: 'ADMIN') if not exists
    - AuthService methods: register, login, getUserById, getAllUsers, updateUserRole
    - updateUserRole throws ForbiddenError if attempting to demote the sole remaining ADMIN
  </behavior>
  <action>
    1. In backend/src/types/auth.ts:
       - Define Zod schemas: RegisterSchema, LoginSchema, UpdateUserRoleSchema.
       - Define User and AuthResponse types.
    2. Export auth types from backend/src/types/index.ts.
    3. In backend/src/db/database.ts:
       - Add CREATE TABLE IF NOT EXISTS users (...)
       - Add users index on email and username
       - In seedInitialData, check if admin user exists; if not, hash password and insert admin.
    4. In backend/src/services/authService.ts:
       - Implement hashPassword(password: string, salt?: string) helper.
       - Implement generateToken(user: User) and verifyToken(token: string) helper.
       - Implement AuthService class with register(), login(), getMe(), listUsers(), and updateRole(id, newRole, callerId).
  </action>
  <verify>
    <automated>npm run test:backend</automated>
  </verify>
  <done>Users table created and AuthService methods unit-tested.</done>
</task>

<task type="auto" tdd="true">
  <name>Task 2: Implement auth & user routes, wire into Express app, and create test suite</name>
  <files>
    backend/src/routes/authRoutes.ts,
    backend/src/routes/userRoutes.ts,
    backend/src/middleware/auth.ts,
    backend/src/app.ts,
    backend/tests/auth.test.ts
  </files>
  <behavior>
    - POST /api/auth/register validates payload, returns 201 with user and token
    - POST /api/auth/login validates credentials, returns 200 with user and token, or 401 on invalid credentials
    - GET /api/auth/me returns currently authenticated user based on Bearer token or x-user-id header
    - GET /api/users returns list of all users, strictly guarded with requireRole(['ADMIN'])
    - PUT /api/users/:id/role updates user role, strictly guarded with requireRole(['ADMIN'])
    - Attempting to demote sole admin returns 400 Bad Request or 403 Forbidden
  </behavior>
  <action>
    1. Create backend/src/routes/authRoutes.ts:
       - POST /register -> AuthService.register
       - POST /login -> AuthService.login
       - GET /me -> AuthService.getMe
    2. Create backend/src/routes/userRoutes.ts:
       - GET / -> requireRole(['ADMIN']) -> AuthService.listUsers
       - PUT /:id/role -> requireRole(['ADMIN']) -> AuthService.updateRole
    3. Update backend/src/middleware/auth.ts:
       - Extract token from Authorization: Bearer <token> if present, validating and setting req.user.
    4. In backend/src/app.ts:
       - Mount authRouter at /api/auth
       - Mount userRouter at /api/users
    5. Create backend/tests/auth.test.ts:
       - Test registration success & duplicate validation
       - Test login success & wrong password rejection (401)
       - Test admin user list retrieval (200 for admin, 403 for member/viewer)
       - Test admin role update (member -> admin, viewer -> member)
       - Test last admin demotion prevention
  </action>
  <verify>
    <automated>npm run test:backend</automated>
  </verify>
  <done>All backend integration tests pass, including auth.test.ts and existing test suites.</done>
</task>
</tasks>
